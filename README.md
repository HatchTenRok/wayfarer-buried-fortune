# 埋蔵量占い

GitHub Pagesで公開するための静的Webアプリです。

## 使うファイル

- `index.html`: アプリ本体
- `styles.css`: 画面デザインと演出
- `app.js`: 地図、検索、演出、ピン表示
- `data/municipalities.json`: 市区町村検索候補
- `data/by_municipality/*.geojson`: 市区町村別の地図データ
- `data/history_by_municipality/*.geojson`: Ver3から自治体別に分割した歴史ピン・街道・近世村
- `data/profiles/*.json`: 全国順位、全国平均、鑑定コメント、風土・歴史カード
- `data/boundaries/*.geojson`: 市区町村別の輪郭データ
- `data/boundary_index.json`: 地図クリック地点から市区町村候補を探すための軽量索引
- `data/story_asset_rules.json`: 鑑定文・候補名とWebP画像を紐づけるカテゴリ定義
- `webp/*.webp`: 鑑定演出に重ねる説明文連動イラスト
- `filter_cafe_restaurant_noise.py`: 飲食店データから施設内食堂、病院、学校、企業、工場系の候補を除外する保守スクリプト
- `filter_wayfarer_ineligible_facilities.py`: 施設名からWayfarer不適合候補を検査・除外する保守スクリプト
- `update_facility_data.py`: 同名ピン統合、障がい者施設除外、P35-18道の駅追加、件数・プロフィール再計算を行う保守スクリプト
- `facility_cleanup_and_road_station_report.json`: 上記データ更新の件数・割当結果
- `indexes/municipality_layer_counts.json`: 市区町村別のカテゴリ件数
- `attribution/`: 出典・ライセンス確認用

## 公開方法

このフォルダの中身をGitHubリポジトリに置き、GitHub Pagesで公開します。
ビルド工程は不要です。

## データ読み込み

アプリは最初に `data/municipalities.json`、`data/boundary_index.json`、`data/story_asset_rules.json` を読み込みます。
市区町村を選ぶと、対応する基本データ、歴史データ、鑑定プロフィール、境界の4ファイルだけを読み込みます。
全国GeoJSONを一括で読まないため、GitHub Pagesでも扱いやすい構成です。

結果画面は3ページ構成です。1ページ目ではWikipedia由来の人物・名所・食文化等を短く総括したタイトルと、件数ルールにもとづく街歩きの手がかり、「街の基盤」「歴史資産」のレーダーチャートを表示します。線の長さには全国順位の百分位、軸の先端には実件数を使います。軸名を押すと結果画面を閉じ、対応カテゴリだけを地図に表示します。地図右側の「復帰」で全カテゴリをONに戻せます。2ページ目は余分なタイトルを置かず、街の鑑定コメント本文だけを表示します。3ページ目はゆかりの人物、観光・歴史名所、食文化、ご当地キャラクターです。各カードは先頭5件を表示し、「ほか○件をすべて見る」でパネル全体へ展開できます。

短い鑑定見出しは件数を加味します。飲食店は全国30位以内だけに言及し、街道・宿場と土木遺産は1件以上、近世村は5件以上で専用の街歩き表現を使います。それ以外のカテゴリは少数件を「充実」と誇張せず、街歩きの手がかりとして案内します。この見出しは1ページ目と「この街を歩くヒント」で共通です。

歴史地名80,296件は、近世村ポリゴンと役割が重なるためランタイムデータから削除済みです。近世村は2015年農業集落境界をもとに復元した概略範囲で、隣接する村を判別しやすいようポリゴン外周を白線表示します。産業遺産559件の地図ピンも削除し、既存の観光名所と重なる名称を統合した473件を242自治体の「観光・歴史名所」へ移しました。

`data/by_municipality/*.geojson` は公開時の通信量とブラウザ負荷を抑えるため、アプリが表示に使うプロパティだけを残した軽量版です。大量のPointを持つ市区町村では、地図上のPoint描画を代表表示に抑え、結果画面の件数は全件集計を表示します。

飲食店データは、施設内食堂、寮、病院・厨房、介護・ケア施設、学校・大学、企業・工場関連施設を名称・住所の語句で除外した版です。元データの店名欄に営業者名や個人名らしい値がある場合、ポップアップでは「飲食店候補」として表示します。

施設系カテゴリは、学校、幼稚園・保育施設、特別支援学校、老人・介護施設、病院・診療所、大学、障がい者施設などに関係する名称を元GeoJSONから除外済みです。公共施設・文化施設の同一自治体内にある同名Pointは座標平均の代表ピン1本へ統合しています。国土数値情報P35-18の道の駅1,145件は公共施設として収録しました。アプリの読み込み時にも不適合施設条件を再確認し、表示件数を再計算します。

鑑定演出のWebP画像は `data/story_asset_rules.json` のカテゴリ語句をもとに、自治体の説明文と候補名から一致したカテゴリをすべて表示します。結果画面を閉じると演出画像も消え、再表示時には再び表示します。鑑定後は右側の小さな「鑑定結果」ボタンから、現在選択中の市区町村の説明を再表示できます。地図上の別地域をクリックすると、下部の「クリックした街を鑑定」ボタンからその地域の鑑定へ進めます。カテゴリメニューは画面高を超えた場合に縦スクロールできます。国土地理院タイルの出典は折りたたまず常時表示します。

ピンの吹き出しはピン上方へ固定しています。画面右上の「鑑定結果」「復帰」はズームボタンの左側に置き、画面幅が変わっても重ならない配置です。地理院タイルの出典は画面最下部に常時表示します。

`build_ver3_integration.py` はVer3 ZIPを再処理する保守用スクリプトです。実行時には使いません。処理結果と割当件数は `ver3_integration_report.json` に保存しています。施設データの更新結果は `facility_cleanup_and_road_station_report.json` に保存しています。

`finalize_history_layers.py` は、歴史地名と産業遺産ピンをランタイムデータから外し、産業遺産名をプロフィールカードへ移す保守スクリプトです。適用結果は `history_layer_cleanup_report.json` に保存しています。
